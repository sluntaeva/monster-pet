# Monster Pet · первый прототип

## Обновление 2026-10-24 — время отсутствия
Сервер учитывает прошедшее время при чтении состояния и перед игровым действием: за полный час сытость −2, настроение −1, энергия +2. За один перерыв учитывается максимум 12 часов; остаток неполного часа сохраняется. Шкалы остаются в пределах 0–100, питомец и покупки не теряются. Расчёт ленивый: без фонового таймера, в том числе при открытом приложении во время следующего обращения к серверу. Время клиента не используется. SQLite автоматически обновляется до схемы v3; для старых профилей отсчёт начинается с обновления, без штрафа за прошлое отсутствие. Проверки: 22 теста и production-сборка прошли.

## Текущий этап: backend подключён
`START.cmd` теперь запускает игру и API вместе. Питомец, выдача героя, действия, монеты и покупки хранятся в SQLite на сервере. Старый браузерный прогресс импортируется при первом локальном входе; данные браузера не удаляются. Подробности запуска, API, Telegram и ограничений: [backend](docs/backend.md). Требуется Node.js 22.17+.

Описания localStorage и отсутствия backend ниже — история ранних этапов; актуальная схема описана в docs/backend.md.

## Дружба с питомцем
Пять уровней: 0/50/150/300/500 XP. Полезная забота +5 XP, завершённый раунд +10 XP; до трёх начислений каждого вида и до 50 XP за сутки UTC. Полные шкалы и касания XP не дают. Полоска дружбы, новые реплики и уведомление о повышении уровня используют серверный прогресс. Дружба не отменяет недовольство при низких шкалах. База автоматически обновляется с v1 до v2 без сброса питомца, монет и покупок. Перед обновлением рабочей базы сохранена копия в work/before-friendship-*.

Подробная инструкция: [telegram-launch.md](docs/telegram-launch.md). Пока бот и адрес отсутствуют — код подключения подготовлен, публикация не выполнена. Локальная игра запускается отдельно через START.cmd.

Обновление 2026-10-22: бот @monster_pet_pixel_bot создан, локальный токен настроен. Подготовлен постоянный хостинг Render: [hosting-render.md](docs/hosting-render.md), render.yaml, раздача клиента и API одним процессом, защищённый Telegram webhook. В hosted-режиме отдельный polling-бот не запускается. Сервис на хостинге пока не создан, публичный URL ещё не выдан.

Phaser 3 + TypeScript + Vite. Буба в пиксельной комнате: дыхание, три действия, реплики, шкалы и локальное сохранение. Иллюстрация создана средствами Phaser, внешние изображения не нужны. Шрифт загружается при наличии сети; предусмотрен системный fallback.

## Запуск
Дважды нажать `START.cmd`, дождаться запуска и открыть http://127.0.0.1:5173 в браузере. Оставить окно запуска открытым. При первом запуске нужен интернет для установки пакетов и установленный Node.js. Открытие index.html двойным щелчком не запускает TypeScript/Vite; теперь в таком случае появляется подсказка.

Из этой папки: `npm install`, затем `npm run dev`. Открыть адрес, который выведет Vite. `npm run build` проверяет TypeScript и создаёт dist; `npm test` проверяет правила состояния. Для повторной установки использовать `npm ci`, если есть package-lock.json.

## Структура
- `src/domain` — типы и чистые правила питомца, без Phaser.
- `src/state` — единое состояние с копиями для чтения.
- `src/services` — контракт хранения и локальная реализация.
- `src/game/scenes` — Boot → Room, фон и выполнение анимаций.
- `src/game/entities` — пиксельный Буба и реакции.
- `src/main.ts` — сборка приложения и доступные DOM-кнопки.
- `docs/architecture.md` — границы первого этапа и дальнейшее подключение Telegram/backend.

Проверить вручную: все три действия, ограничение шкал 0–100, блокировку повторных кликов на время реакции, сохранение после перезагрузки, узкий экран. Очищение данных сайта сбрасывает прогресс.

Это локальный прототип: авторизация Telegram, сервер, расчёт отсутствия, мини-игра и платежи ещё не реализованы.

## Стартовый тест
При первом входе показаны четыре вопроса. Шанс каждого героя: 15% + 10% за каждый соответствующий ему ответ (от 15% до 55%). Результат выбирается один раз и сохраняется в отдельном ключе localStorage `monster-pet:onboarded:v1`. Старое сохранение комнаты с Бубой остаётся нетронутым; после обновления впервые будет предложен тест. Герои пока используют варианты одного временного спрайта, имена и характеры различаются. Выдача происходит в браузере; серверная защита однократного выбора появится с backend. При недоступном хранилище результат сохраняется только на текущую сессию.

После добавления теста production-сборка и четыре автоматических теста прошли. Проверены все 256 сочетаний ответов, границы интервалов выпадения, сумма вероятностей, состояние питомца и некорректные данные. Визуальная проверка сценария в браузере ещё требуется. Предыдущие ограничения установки ниже относятся к раннему этапу; зависимости теперь установлены.

## Мини-игра «Лови вкусняшки»
В комнате под действиями доступна кнопка начала раунда. 30 секунд активной игры: движение указателем/пальцем или стрелками влево-вправо, печенье +1, носок −2 (счёт не ниже нуля). В конце автоматический возврат в комнату и итог. Питомец соответствует результату стартового теста.

Первые три результативных раунда за день UTC дают монеты: 1–7 очков → 5, 8–14 → 10, 15+ → 15. Нулевой результат не расходует лимит. После лимита играть можно без награды. Баланс сохраняется локально; это прототип экономики без серверной защиты, монеты пока не тратятся. Обновление страницы прерывает раунд без награды. Длительные паузы между кадрами не проматывают таймер.

Проверить вручную: сенсорное и клавиатурное управление, столкновения, конец 30-секундного раунда, возврат в комнату, сохранение монет, три награды и следующий раунд без начисления.
