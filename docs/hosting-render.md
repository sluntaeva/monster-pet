# Постоянный HTTPS-адрес на Render

Подготовлено 2026-10-22. Сервис ещё не создан, публичного адреса нет, оплата не выполнялась.

## Готовая конфигурация
render.yaml описывает один Node.js Web Service и постоянный диск 1 ГБ. Этот же сервис отдаёт dist, обслуживает API и принимает Telegram webhook: отдельный платный worker для бота не нужен. При старте на Render определяется RENDER_EXTERNAL_URL, устанавливаются меню «Играть» и webhook. База лежит в /var/data/monster-pet.sqlite. Локальный dev-вход выключен. Секрет бота вводится в Render, секрет webhook генерируется платформой.

Нужны аккаунт Render и Git-репозиторий с содержимым папки monster-pet. Локальные .env, data, work и node_modules не загружать. Репозиторий можно сделать приватным. В Git нельзя помещать токен, базу и локальные резервные копии.

## Стоимость
Ориентир по проверенным 2026-10-22 тарифам: вычислительный сервис 512 МБ $7/месяц плюс диск 1 ГБ $0,25/месяц, суммарно около $7,25 до налогов и дополнительных расходов за использование. Перед созданием сверить цену в панели. Бесплатная файловая система без постоянного диска не подходит для текущей SQLite-базы: данные могут исчезнуть при рестарте/деплое.

Источники: [цены Render](https://render.com/pricing), [постоянные диски](https://render.com/docs/disks), [render.yaml](https://render.com/docs/blueprint-spec).

## Размещение
1. Создать/войти в Render, подключить GitHub/GitLab с проектом. Если аккаунта Git тоже нет, его нужно создать отдельно.
2. Создать Blueprint из репозитория, выбрать render.yaml. Если код находится в подпапке репозитория, задать root directory этой папки; проще отдельный репозиторий с Monster Pet в корне.
3. Проверить план, стоимость и постоянный диск /var/data. BOT_TOKEN вставить из локального .env в секретное поле Render. Не вставлять в чат, URL или исходники.
4. После согласия со стоимостью создать сервис. Дождаться успешного Build и Deploy. Render выдаст собственный постоянный адрес вида https://<имя-сервиса>.onrender.com; конкретный URL заранее не существует и не гарантируется.
5. Проверить https://<реальный-адрес>/api/health. В логах должно быть «Telegram menu and webhook configured». Остановить старый polling-процесс npm run bot, если он запускался: webhook и polling одновременно не используются.
6. Открыть @monster_pet_pixel_bot, отправить /start, нажать «Играть». Существующий webhook переключается на этот новый адрес при запуске настроенного сервиса. Параметр drop_pending_updates=false сохраняет очередь обновлений.

Токен передаётся только Render как секрет сервера и официальному API Telegram при настройке/ответах. Постоянная публикация делает клиент игры общедоступным, пользовательские данные API остаются под Telegram-авторизацией.

## После запуска
Скопировать фактический адрес в локальный .env: APP_URL и APP_ORIGIN. Это не обязательно для работы самого Render, который использует RENDER_EXTERNAL_URL; нужно для согласованности локальной конфигурации. Не запускать локальный polling поверх webhook.

Новый публичный сервер создаст Telegram-профиль при первом входе. Локальный dev-питомец и база автоматически на хостинг не переносятся. Сервис и база рассчитаны на один экземпляр. Настроить внешние резервные копии и проверить восстановление до широкого запуска.

## Проверки подготовки
Раздача HTML/ассетов и недоступность .env/исходников проверяются локальным HTTP-тестом. Webhook без правильного секрета отклоняется; production dev-вход запрещён. Реальная регистрация webhook, адрес Render и запуск Mini App требуют созданного сервиса и пока не проверены.
