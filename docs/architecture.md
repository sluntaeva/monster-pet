# Архитектура первого этапа

## Обновление: серверный этап
Текущая схема: DOM/Phaser → GameApi → HTTP API → SQLite. Серверная выдача героя, действия, награды, покупки и сессии реализованы. Для локального запуска выбран встроенный HTTP Node.js и SQLite вместо ранее предложенных Fastify/PostgreSQL. Переход на PostgreSQL возможен отдельным этапом. Подробная актуальная архитектура и проверки: [backend.md](backend.md). Ниже сохранено описание начального клиентского этапа.

Основание: 14 заметок проекта в Obsidian Vault, проверены 2026-10-21. Код хранится отдельно от Vault, исходные заметки не менялись.

## Сейчас
DOM UI → PetStore → чистая функция applyAction → PetRepository. Параллельно UI просит RoomScene проиграть реакцию Monster. Сцена отвечает только за изображение и блокировку анимации; правила не зависят от Phaser. BootScene переключается в RoomScene. Отдельная PreloadScene появится при добавлении ассетов; сейчас текстура генерируется кодом. DOM заменяет UIScene на первом этапе ради клавиатурной доступности и адаптивной вёрстки.

Хранилище localStorage — только прототип. Ошибочный формат сбрасывается к начальному состоянию, невозможность записи показывается пользователю. Действия применяются и сохраняются при принятии, анимация лишь отображает результат. Одновременные нажатия блокируются до её завершения. Пока нет ухудшения состояния со временем, наград и сетевых запросов.

## Далее
1. Ассеты: атлас и анимации четырёх героев, PreloadScene, конфиги персонажей вместо ветвлений по сценам.
2. OnboardingScene: тест и серверная однократная выдача; результат всегда приходит с backend.
3. Адаптер Telegram: ready/expand, safe area, изменение viewport и возврат из фона; fallback для обычного браузера.
4. Async API repository и store с loading/error/retry; серверный снимок является источником истины. Локальное хранилище остаётся только кешем. Миграция локального прогресса не предполагается.
5. Backend TypeScript/Fastify + PostgreSQL: проверка initData и auth_date, сессии, транзакционные действия с request_id и версией, серверное время и расчёт отсутствия. Токен бота только на сервере.
6. Отдельная MiniGameScene, проверка результатов и лимитов награды. Платежи после проверки удержания.

## Проверки
Чистые правила: границы, отсутствие мутаций, повреждённое сохранение. Сборка: TypeScript и Vite. Браузер: появление сцены, реакции, сохранение и мобильная компоновка. Перед Telegram-релизом обязательны тесты реальных Android/iOS клиентов и сетевых повторов.

Официальные источники: [Phaser — установка](https://docs.phaser.io/phaser/getting-started/installation), [Phaser — сцены](https://docs.phaser.io/phaser/concepts/scenes). Phaser закреплён на 3.90.0, переход на другую основную версию не предполагается.
