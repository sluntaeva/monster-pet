# Backend Monster Pet

## Готово
Node.js 22.17+ / TypeScript, встроенный HTTP-сервер и SQLite (`node:sqlite`). Отдельный PostgreSQL или установка нового пакета не нужны. Это осознанное упрощение первоначального плана Fastify/PostgreSQL для локального MVP. SQLite в установленной версии Node выводит предупреждение ExperimentalWarning.

Игра использует сервер для состояния питомца, стартового теста, действий, раундов, наград, монет, покупки и выбора ковра. Компоненты Phaser отвечают за изображение и реакции, правила выполняются на сервере. Состояние обновляется в интерфейсе после успешного ответа; при ошибке показано сообщение. Результат мини-игры можно отправить повторно, не начиная новый раунд.

## Запуск
`START.cmd` или `npm run dev` из папки проекта запускает два процесса: Vite на 127.0.0.1:5173 и API на 127.0.0.1:3001. Vite пересылает `/api` на backend. Оба процесса завершаются при остановке общего запуска. Перед переходом со старого запуска остановить прежний сервер, иначе порт будет занят. Изменения в backend требуют перезапуска; frontend обновляется автоматически.

API отдельно: `npm run server`. Локальный вход включается только при `DEV_AUTH=1`; общий dev-запуск задаёт его автоматически. База: `data/monster-pet.sqlite`, рядом возможны WAL/SHM-файлы. Папка data исключена из Git. Нужен Node.js не ниже 22.17.

## Профили и перенос
В dev-режиме локальный профиль определяется случайным идентификатором устройства в localStorage. Сессия в HttpOnly-cookie действует 7 дней; после истечения сессии профиль определяется тем же идентификатором. При первом создании dev-профиля импортируются старый питомец, баланс и покупки из браузера; существующая серверная запись не перезаписывается. Старые локальные данные не удаляются. Импорт разрешён только в локальном dev-входе — для Telegram пользователь не может передать себе произвольный баланс.

Очистка всех данных сайта удаляет локальный идентификатор dev-профиля, поэтому серверный аккаунт перестанет быть доступен из этого браузера. В Telegram профиль привязан к подтверждённому Telegram ID. Старый dev-профиль автоматически с Telegram-аккаунтом не объединяется.

## API
| Метод | Путь | Данные |
|---|---|---|
| GET | /api/health | Готовность сервера |
| POST | /api/auth/dev | deviceId, опциональные pet/wallet для первого импорта |
| POST | /api/auth/telegram | initData |
| GET | /api/state | Серверный снимок |
| POST | /api/onboarding | answers |
| POST | /api/pet/actions | action: feed/play/rest |
| POST | /api/shop/buy | item |
| POST | /api/shop/equip | item или null для обычного ковра |
| POST | /api/minigames/start | Выдаёт runId |
| POST | /api/minigames/finish | runId, score |

Все игровые POST дополнительно требуют `requestId` и актуальную `version`. Снимок содержит pet (или null до теста), wallet, version и serverTime. Cookie: mp_session, HttpOnly, SameSite=Strict, путь /api; в production дополнительно Secure. Клиент не передаёт ID игрока: сервер берёт его из сессии.

## Защита и целостность
SQLite-транзакция объединяет изменения состояния и сохранение квитанции запроса. Одинаковый requestId с тем же содержимым не повторяет действие; другое содержимое с тем же ID отклоняется. Старая версия даёт 409, клиент перечитывает состояние. Покупка проверяет стоимость и владение, экипировать чужой предмет нельзя. Игра начисляет только первые три результативных раунда за сутки UTC, повторно завершённый раунд не даёт монеты.

Сервер требует разрешённый Origin для POST, JSON, тело не более 16 КиБ, ограничивает частоту запросов. Dev-вход доступен только с loopback и запрещён в production. Сессии хранятся в базе в виде хеша случайного токена, истёкшие сессии удаляются при входе. Секреты и initData не записываются в логи.

Мини-игра: проверяются владелец раунда, длительность 29,5 секунды — 2 часа, целочисленный счёт 0–49 и однократное завершение. Новый раунд нельзя начать раньше 30 секунд после предыдущего. **Это базовые проверки, а не полный античит**: подделанный счёт внутри допустимых границ пока не выявляется. Следующий этап — серверный seed и проверка журнала действий либо серверная симуляция.

## Telegram и production
Требуются реальный бот, HTTPS-домен и размещение сервера. В `.env` задаются `BOT_TOKEN`, `APP_ORIGIN=https://...`, `NODE_ENV=production`, `DEV_AUTH=0`; пример полей есть в `.env.example`. Токен не помещать в frontend или Git. Запускать `npm run server`, перед ним reverse proxy с HTTPS: `/api` → 127.0.0.1:3001, остальное → файлы dist после `npm run build`. Установка зависимостей должна включать tsx (текущий запуск исполняет TypeScript).

Вход принимает подписанный initData из Telegram SDK либо параметра tgWebAppData в URL-фрагменте. Проверяются HMAC-SHA256, отсутствие повторных полей, auth_date (не старше часа и не более 30 секунд в будущем) и ID пользователя. [Алгоритм Telegram](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), просмотрен 2026-10-21. В обычном браузере production-сборка просит открыть игру через Telegram. Без реального бота end-to-end Telegram-вход пока не проверен.

## База и резервирование
Текущее обновление схемы — v2: в accounts добавляется friendship с XP, дневным лимитом и счётчиками событий. Переход с v1 выполняется транзакционно без пересоздания таблицы и потери прогресса/сессий. XP начисляется в той же транзакции и квитанции, что и игровое действие или завершение раунда; отдельного клиентского API для произвольного начисления опыта нет.

Начальная схема v1: accounts, sessions, receipts, runs. Пока это один процесс и один файл базы, не кластер. Для резервирования остановить API и скопировать базу в отдельное безопасное место, затем запустить API; восстановление проверить на отдельной копии. Безопасное онлайн-резервирование, последующие миграции, очистка старых квитанций/раундов, удаление аккаунта и мониторинг — следующие эксплуатационные задачи.

## Проверки и оставшаяся работа
13 автоматических тестов проходят, включая базу на диске после повторного открытия, Telegram-подпись/просрочку/подделку, HTTP-вход, запрет чужого Origin, повторные действия, конфликты версий, награды и покупки. В браузере проверены перенос Няма и баланса, действие и восстановление энергии после обновления. Полный сенсорный раунд и реальный Telegram-вход требуют проверки.

Расчёт отсутствия, ежедневная цель, серверный античит, Telegram-бот и публикация на хостинге пока не реализованы. Платежей нет. Локальный API запущен только на этом компьютере.
